## Run focus

- 2026-11-25 — Added a per-run "run focus" to the Last run sentence and the ontology. Source: `analysis/athlete_profiles` (the athlete clusters "Interval-focused", "Efficient & consistent", "Fast starter / developing"; k-means/GMM, so there are NO fixed thresholds in the notebook). `analysis/run_types` (fartlek, tempo, …) was not used. Because the notebook labels athletes and the CSV has no per-run time series (`site/data/timeseries.csv` covers only ~120 runs), `site/summary.js` has `runFocus(workoutType, speedMean, hrMean)` with the closest per-run values, checked in this order (one focus per run):
  1. **Interval focused** = `workout_type == INTENSIVE` (the notebook names that cluster by `share_intensive`: ~37% INTENSIVE runs vs ~3% for the others).
  2. **Efficient focused** = `100 * speed_mean / hr_mean >= 7.1` (notebook `efficiency`; cluster means 7.70 vs 6.48/6.57, 7.1 = midpoint, my choice, not a notebook value).
  3. **Fast start focused** = all other runs (low efficiency, not interval). Substitute: the notebook's `opening_pace_ratio` (first 15% of the run) is not in the CSV.
  Counts on the real 40,186-row CSV: Efficient 23,120, Fast start 14,966, Interval 2,100.

## Running KPIs

- 2026-11-25 — Built the 6 computable KPIs from `docs/running_dashboard_kpis.json` into the runner dashboard. Panel "My training KPIs" (`#kpi-panel` in `site/index.html`, runners only) shows the cards for the current Beginner/Expert mode and re-renders on toggle. Runner = the run-history runner by default; a "Runner ID" box + Show switches to any runner id (message if no runs; reset on login/logout). All maths is in `site/summary.js` (KPI section, documented constants at its top) and uses REAL `start_date`/`duration_min`/HR columns of `workouts.csv` for that one runner, never the fabricated history timestamps. `timeseries.csv` is fetched lazily, only in Expert mode. "Now" = the runner's last real run (data is historical, 2007–2016); ISO weeks (Monday start).
  - **Beginner**: (1) weekly consistency: active weeks of span, longest + latest streak (weeks in a row with >= 1 run), avg runs / active minutes per active week, last 8 ISO weeks incl. empty ones. (2) session summaries: last 5 runs (date, km, minutes, pace m:ss/km from `speed_mean` = 60/speed) + combined total; each line is built from triples (`sessionTriples` → `buildSessionLine`). One placeholder card for the skipped goal-tags / route-environment KPIs.
  - **Expert** (compact wording, per-run lines built from `metricTriples` → `buildExpertRunLine`): (3) TID over the latest 10 runs, shown overall AND split by source ("time-series" vs "summary estimate", with run count/minutes each). (4) coupling: r(HR, speed), r(beats/km, ascent m/km), median beats/km (= hr_mean × pace), last 5 runs with beats/km vs median and, for series runs, within-run r(HR, speed). (5) periodization: last 8 ISO weeks of km, minutes, intensity score, acute (week load) / chronic (mean of 4 weeks) ratio + status, volume and intensity trend slopes. (6) strain: last 6 runs' hr_mean vs expected HR for their speed (line HR~speed fitted on the earlier runs), residual in bpm, flag at >= +5 bpm, within-run drift % for series runs >= 20 min. One placeholder card for plan adherence.
- **Fallback rules / cutoffs (my choices, also in code comments):** reference HRmax = runner's highest `hr_max`, floored at 170 (age unknown). Zones: low < 80 %, moderate 80–90 %, high >= 90 % of it. Zone source per run: time-series (time-weighted by gap to next sample) if the workout is in `timeseries.csv` (120 runs, 100 runners); else ESTIMATED from the summary: normal curve with mean `hr_mean`, sd `hr_std` (or (hr_max−hr_mean)/2 if 0), truncated to [`hr_min`, `hr_max`]. Note this uses `hr_std`/`hr_min` too, not only `hr_mean`/`hr_max`. Load = minutes × (1·low + 2·mid + 3·high share) (Edwards-style, no resting HR needed); intensity score = load/minutes. ACWR status: < 0.8 low, 0.8–1.3 balanced, > 1.3 high. Strain baseline = earlier runs (all but latest 6; all runs if < 5 earlier; mean HR if speeds don't vary). Runs missing date/duration/speed/hr_mean/distance are skipped (none in the real data). For the 120 series runs the series means equal the summary columns (diff < 0.05), so means/ascent come from the summary and the series only adds zones, within-run r and drift.
- **Known quality caveat:** over the 120 series runs the summary-based estimate differs from the real series zones by a mean 6.3 / 10.0 / 5.6 percentage points (low/mod/high; estimate biased +4.0 low, −4.4 high), so estimated TID is rough — that is why each number is labelled with its source.
