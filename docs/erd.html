Endomondo HR dataset: data model

40,186 running workouts from 761 athletes. The source parquet has one row per workout, with the time series stored as list columns. Logically that is three entities: an athlete does many workouts, and each workout has 500 timesteps. The workout type is a fourth, small lookup.

Stored in the dataset Derived (computed from workouts) Lookup / label PK primary key FK foreign key Line ends: || exactly one, crow's foot = many

Things to know before modelling

  • The label is HR-based. workout_type lines up with hr_mean ranges, so predicting it from HR features is trivial. Leave HR out, or create your own labels.
  • Splits are by workout, not by athlete. 673 of the 761 athletes appear in more than one split. A model can learn athletes instead of patterns. Re-split on user_id if you want honest scores.
  • Fixed length. Every workout has exactly 500 timesteps, so a 60-minute and a 120-minute run have different time gaps between points. Use timestamp, not the step index, for time.
  • Pre-cleaned. Series are smoothed (7-point moving average) and filtered: hr_mean ≥ 120, hr_max ≤ 200, hr_std ≥ 5. Very easy runs and walks were removed.
  • Imbalanced classes. INTENSIVE is only 5% of workouts.
